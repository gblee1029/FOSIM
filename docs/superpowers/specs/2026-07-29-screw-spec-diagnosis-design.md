# 나사 사양 기반 진단 설계

## 목적

나사 사양을 선택적 입력으로 추가하여, 토크만으로는 표현할 수 없는 불량 유형 — 나사 갈림,
헛돎, 크로스 스레드 — 을 진단하고, 태핑 나사에서 착좌 검출이 오작동하는 문제를 해소한다.

## 문제

현재 FOSIM의 분석 경로에는 나사 정보가 전혀 없다. settings CSV에 `screw_position`과
`joint_type`이 있으나,

- `screw_position`은 위치 라벨(`S01`)이지 사양이 아니다.
- `joint_type`(`HARD`/`SOFT`)은 `csv_import.py:79` → `routes.py:140`을 거쳐 DB에 저장될 뿐
  **어떤 분석 코드도 읽지 않는다.** 사실상 죽은 메타데이터다.

따라서 엔진은 지금 보고 있는 파형이 M3인지 M8인지 모르는 채 절대 임계치로 판정한다.
`docs/limitations.md`에도 나사 피치와 마찰 변동이 모델링되지 않았다고 이미 기록되어 있다.

## 확보 가능한 입력

운용 측에서 제공 가능한 범위가 확인되었다.

- **나사 사양은 확보 가능**: 호칭경, 피치, 길이, 강도구분, 나사 종류.
- **기대 체결깊이는 확보 불가.** 이를 필요로 하는 룰은 제외하거나 재구성해야 한다.
- **각도 로깅은 기본 비활성**이며 장비에서 켜야 한다. 현재 데이터에는 없거나 일부만 있다.
  따라서 각도 의존 진단은 오류를 내거나 침묵하지 않고 **단계적으로 축소 동작**해야 한다.

## 접근

나사 사양 컬럼을 선택적으로 추가하고, 각 진단 룰을 그 룰이 실제로 요구하는 데이터에 대해
게이팅하며, 룰이 비활성인 사유를 응답에 명시한다. 사양만 있어도 임계치 정규화와 착좌 검출
분기는 오늘 동작한다. 각도 로깅이 켜지면 각도 룰이 추가 변경 없이 자동으로 활성화된다.
이로써 **각도 로깅 도입 일정에 개발 일정이 묶이지 않는다.**

사양만 활용하는 축소안(각도 룰 없이 정규화만)은 최종 목표로는 기각했다. 본 설계의 부분집합에
불과하며, 이 작업을 촉발한 신규 불량 유형을 전혀 얻지 못한다. `screw_id`로 참조하는 별도
나사 마스터 테이블은 정규화 관점에서 우수하나 임포트가 2파일에서 3파일로 늘고 마스터 관리
UI가 필요해진다. 사이클 규모가 정당화할 때 나중에 이관한다.

## 구성 요소

### 1. 나사 사양 필드

settings CSV에 선택적 컬럼 5개를 추가한다.

| 컬럼 | 예시 | 용도 |
|---|---|---|
| `screw_nominal_dia` | `3.0` | 임계치 정규화 기준 |
| `screw_pitch` | `0.5` | 각도 → 진입량 변환 |
| `screw_length` | `8.0` | 프리런 회전각 절대 상한 |
| `screw_grade` | `8.8` | 저장만 함. 본 스펙 범위 밖 |
| `screw_type` | `MACHINE` / `TAPPING` / `THREAD_FORMING` | 룰 분기 |

전부 선택적이며, 없으면 현재와 동일하게 동작한다.

`screw_type`은 각도 룰과 무관하게 독자적 가치가 있다. 태핑·탭타이트 나사는 **설계상**
프리런 구간에서 토크가 상승하는데, 현재 착좌 검출기는 그 상승을 착좌로 읽는다. 4절 참조.

신규 모듈 `backend/app/services/screw_spec/`가 필드 파싱과 검증을 맡고, 파생값을 계산한다 —
최대 가능 회전각 `(length / pitch) × 360`, 정규화 계수 등. 검증은 호칭경 대비 말이 안 되는
피치 같은 오타 입력을 잡는다.

### 2. 각도 가용성 감지

각도는 세 상태 중 하나로 들어오며, 사용자 신고가 아니라 **파형에서 판별**한다.

```text
angle 컬럼 없음                        → 각도 룰 전체 비활성
angle 시계열에 0 근처로의 급락 존재    → 착좌 리셋 기준
착좌 시점 각도가 전체 각도 범위에서
  큰 비중을 차지                       → 절대 기준
그 외                                  → 판별 불가. 보수적으로 착좌 리셋 취급
```

리셋 기준 판별은 보너스를 준다. 장비가 각도를 리셋한 지점은 **장비 자신의 착좌 판단**이며,
이는 룰 기반 착좌 마커의 독립적 검증자가 된다 — `docs/waveform-analysis.md`가 이벤트 코드에
할당해 둔 역할이다. 둘이 크게 어긋나면 그 자체가 경고 신호다.

게이팅 결과는 응답에 실려, 사용자가 무엇을 켜야 하는지 알 수 있게 한다.

```json
"capabilities": {
  "freerun_over_rotation": {"available": false, "reason": "각도 기준이 착좌 리셋형"},
  "thread_stripping":      {"available": true},
  "clamp_angle_range":     {"available": false, "reason": "joint_type 미지정"}
}
```

### 3. 신규 진단 룰

기존 5종과 나란히 추가하며, 현재 룰은 변경하지 않는다.

**① 프리런 과회전** — 절대 각도, 길이, 피치 필요.
프리런 회전각이 `(length / pitch) × 360`을 초과하면 물리적으로 불가능한 상태이며, 헛돎,
탭 불량, 나사 미삽입, 오조립을 뜻한다. **기준 사이클도 체결깊이도 없이 물리만으로 판정에
도달하는 유일한 룰**이다.

**② 나사 갈림 / 스트리핑** — 각도만 필요, 기준점 무관.
착좌 후 각도는 계속 증가하는데 토크-각도 기울기가 클램프 초기 대비 붕괴한다. 착좌 리셋형
각도에서도 동작하므로 **각도 로깅이 켜지는 즉시 사용 가능**하다. 각도 룰 중 우선순위 최상.

**③ 클램프 회전각 범위 이탈** — `joint_type` 필요.
착좌에서 목표 토크까지의 회전각이 HARD/SOFT 기대 밴드를 벗어난다. HARD인데 클램프 회전각이
크면 들뜸, 개스킷 개재, 이물이다. 이 룰을 위해 `joint_type`을 메타데이터에서 분석 경로로
처음 연결한다.

**④ 크로스 스레드 의심** — `screw_type = MACHINE`일 때만.
프리런 토크가 비정상적으로 높고 변동이 크다. 태핑 나사는 이것이 정상이므로 타입 분기는
최적화가 아니라 **필수**다.

### 4. 착좌 검출 수정 (각도 불필요)

가장 큰 이득은 각도를 전혀 필요로 하지 않는다.

`docs/waveform-analysis.md`의 착좌 검출은 단일 토크 구배 임계치다. 태핑·탭타이트 나사는
나사산을 절삭하거나 성형하는 정상 과정으로 프리런에서 토크가 오르므로, 현재 검출기는 착좌를
너무 이르게 잡는다. 그 오차는 이후 단계 — 특징 추출, 진단, 시뮬레이션 — 전부로 전파된다.

착좌 검출을 `screw_type`으로 분기한다. 각도 로깅과 무관하게 오늘 고칠 수 있고, 본 스펙에서
파급 범위가 가장 넓다.

임계치 정규화도 포함하되 효과는 이보다 작다. `target_torque` 기준 상대 정규화가 호칭경보다
더 많은 일을 하며, 나사 사양은 주로 **입력 검증**(이 나사에 이 목표 토크가 타당한가) 역할이다.

## 검증

- 회귀: 신규 컬럼이 없는 settings CSV가 바이트 단위로 동일한 결과를 내며, 기존
  `backend/tests/test_api_contract.py`의 단언이 유지된다.
- `scripts/generate_sample_data.py`에 합성 파형 4종 추가: 갈림, 헛돎, 크로스 스레드,
  정상 태핑 사이클.
- 게이팅 매트릭스: {각도 없음, 절대, 리셋} × {사양 있음, 없음} 모든 조합에서 `capabilities`
  응답이 올바른지.
- 착좌 검출: 태핑 나사 파형에서 착좌가 태핑 구간 내부가 아니라 그 이후에 찍히는지.

## 리스크와 한계

실측 SH-2 데이터 없이 정한 임계치는 `docs/limitations.md`에 기록된 "starter values"를 하나
더 늘린다. **프리런 과회전만 절대적 물리 판정**이고, 갈림·클램프 회전각·크로스 스레드는 모두
실제 사이클 대비 캘리브레이션이 필요하다. 응답과 UI는 모든 룰을 동등하게 제시하지 말고 이
신뢰도 차이를 표현해야 한다.

축력 추정(`T = K·D·F`)은 명시적으로 범위 밖이다. 나트팩터 K는 도금과 윤활에 따라 대략
±30% 변동하므로, 측정된 마찰 데이터 없이는 판정 근거가 아니라 참고값에 그친다.

## 복수 사이클 최적화와의 관계

`2026-07-29-multi-cycle-robust-optimization-design.md` 참조. 진단 출력이 해당 스펙의 배제
정책을 구동하므로, 본 룰들은 최적화 기준 집합의 품질을 직접 개선한다. 두 스펙은 독립적으로
구현 가능하며, **복수 사이클 쪽이 먼저**다.
